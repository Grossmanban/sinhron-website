Глоссарий

Термины простыми словами.

Короткий словарь терминов, которые встречаются в документации Sinhron. Объясняем простыми словами — без формул.

Термины

Сквозное шифрование (E2EE)

Шифрование «от устройства до устройства»: сообщение зашифровывается на телефоне отправителя и расшифровывается только на телефонах получателей. Сервер в середине видит лишь шифротекст и не может его прочитать.

MLS

Messaging Layer Security, RFC 9420 — стандарт IETF для сквозного шифрования в группах. В Sinhron каждый чат, даже личный, — это группа MLS. Мы используем реализацию OpenMLS.

Группа и эпоха

Группа MLS — это участники чата и общие для них ключи. Каждый раз, когда состав группы или ключи меняются, группа переходит в новую эпоху — с новыми ключами. Ушедший участник не получает ключей новой эпохи, а новичок — ключей старых.

KeyPackage

«Ключ для приглашения», который приложение заранее публикует на сервере. Благодаря ему вас можно добавить в чат, даже когда вы не в сети: собеседник берёт ваш KeyPackage с сервера и создаёт группу.

Forward secrecy

Прямая секретность: если ключ украдут сегодня, прошлые сообщения всё равно останутся закрытыми — старые ключи уже удалены.

Post-compromise security

Восстановление после взлома: даже если злоумышленник получил доступ к ключам, после очередной смены ключей группы он снова перестаёт читать новые сообщения.

SFrame

Secure Frame, RFC 9605 — стандарт шифрования аудио- и видеокадров в звонках. Ключи SFrame выводятся из группы MLS чата, поэтому медиасервер пересылает кадры, но прочитать их не может.

SFU

Selective Forwarding Unit — медиасервер, который принимает видео и звук от каждого участника звонка и пересылает остальным, не смешивая и не расшифровывая. В Sinhron роль SFU выполняет LiveKit.

LiveKit

Медиасервер с открытым кодом для звонков через WebRTC. Разворачивается рядом с сервером Sinhron и пересылает кадры, зашифрованные SFrame.

TURN/STUN (coturn)

Технологии, которые помогают устройствам за NAT и строгими firewall соединиться для звонка. STUN подсказывает устройству его внешний адрес, TURN при необходимости пересылает трафик через себя. В Sinhron это делает coturn, в том числе через порт 443.

Sealed sender

«Запечатанный отправитель» — схема, при которой сервер доставляет сообщение, не зная, кто его отправил. В Sinhron каждый получатель получает сообщение в своём запечатанном конверте (HPKE, RFC 9180), поэтому сервер не знает, к какому чату оно относится. Когда ключи доступа разошлись по чату, конверты уходят без входа в аккаунт — и сервер не знает, с какого аккаунта они отправлены. Первые сообщения нового чата пока уходят с входом в аккаунт. IP-адрес тоже можно скрыть — необязательным прокси Tor.

BIP-39 и ключ из 24 слов

BIP-39 — стандарт, превращающий случайный ключ в последовательность обычных слов. Из ваших 24 слов выводятся все ключи аккаунта; это единственный способ восстановить аккаунт на новом устройстве.

Код безопасности

60 цифр (12 групп по пять), вычисленных из ключей двух собеседников. Если коды на обоих телефонах совпадают, между вами никто не вклинился. Сверить код можно при встрече или по QR.

SQLCipher

Версия базы данных SQLite, которая шифрует файл целиком. В ней Sinhron хранит на устройстве чаты, сообщения и ключи от файлов.

Self-hosting

Размещение сервиса на собственном сервере вместо чужого облака. Sinhron задуман именно так: сервер разворачивает тот, кому доверяют пользователи, — вы, ваша команда или друг.

Метаданные

Данные о переписке, а не её содержимое: кто, кому, когда и примерно сколько пишет, с каких IP-адресов. Сквозное шифрование прячет содержимое, но часть метаданных сервер видит неизбежно — их список приведён в разделе Безопасность.
