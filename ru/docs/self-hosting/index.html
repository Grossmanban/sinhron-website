Свой сервер

Установка сервера

От чистой VM до работающего сервера: Docker, TLS, звонки, бэкапы.

Sinhron работает на сервере, которому доверяете вы. Это руководство проведёт от пустой виртуальной машины до работающего сервера с сообщениями и звонками. Оно рассчитано на человека, который уверенно чувствует себя в Linux и Docker: например, если вы хотите поднять Sinhron для себя, семьи или небольшой команды.

Ранняя бета

Серверная часть работает и покрыта тестами, но проект в ранней бете. Звонки через NAT на развёрнутом сервере ещё не прошли приёмку на реальных устройствах. Делайте резервные копии и не рассчитывайте пока на Sinhron как на единственный канал связи.

Из навыков пригодятся: базовый Linux (ssh, ufw, systemd), Docker и Docker Compose, умение завести DNS-записи. Предполагается, что домен у вас уже есть, а вход по SSH настроен по ключу.

Для звонков нужен публичный IP прямо на сетевом интерфейсе машины. Если провайдер выдаёт адрес через 1:1 NAT (так бывает у AWS Elastic IP и некоторых облаков), звонки тоже можно настроить, но надёжнее обычный VPS.

Подготовка сервера

Обновите систему, заведите отдельного пользователя и откройте нужные порты:

Заметка

Порты, которые публикует Docker (80, 443, 7881, 7882), обходят ufw: Docker пишет собственные правила iptables. coturn работает в сети хоста, и его ufw видит. Если у провайдера есть внешний firewall (security group), откройте там тот же список портов.

Затем запретите вход под root и по паролю (PermitRootLogin no и PasswordAuthentication no в /etc/ssh/sshd_config), установите Docker и войдите под новым пользователем:

Секреты генерируются так:

Несколько важных деталей:

  • TURN_EXTERNAL_IP — публичный IP машины. Если адрес выдан через 1:1 NAT, укажите его в виде публичный/приватный. Без этой переменной compose откажется стартовать.
  • TURN_TTL_SECS — срок жизни временных данных TURN, по умолчанию 86400 секунд (сутки); он же ограничивает максимальную длину звонка.
  • LIVEKIT_URL задавать не нужно: compose сам сообщит клиентам адрес wss:// на имени SINHRON_LIVEKIT_HOSTNAME.
  • Порядок в TURN_URLS — порядок попыток подключения: сначала UDP, потом TCP, затем TLS на 443 для сетей, где открыт только HTTPS.
  • Сейчас compose передаёт серверу не все переменные из шаблона: настройки пула Postgres (SINHRON_PG_*), лимиты (SINHRON_RATE_*) и SINHRON_RETENTION_SWEEP_SECS до контейнера не доходят, и сервер работает со значениями по умолчанию.
  • Спецификация проекта рекомендует хранить секреты в продакшене через Docker secrets или sops; файл .env с правами 600 — минимально допустимый вариант.

Теперь соберите и запустите сервисы:

Только с -f docker-compose.yml

В продакшене всегда запускайте compose с явным -f docker-compose.yml. Рядом лежит docker-compose.override.yml для локальной разработки: он открывает служебные порты, выключает Caddy и переводит coturn в другую сеть. Голый docker compose up -d подхватит его автоматически.

TLS и домен

Перед всеми сервисами стоит Caddy — он сам получает и продлевает сертификаты Let's Encrypt для всех трёх имён (через порт 80) и перенаправляет HTTP на HTTPS. Конфигурация лежит в server/Caddyfile, копировать её никуда не нужно.

Образ Caddy собирается из server/Dockerfile.caddy: это Caddy 2.11.7 с модулем caddy-l4, которого нет в стандартном образе. Он нужен, чтобы делить TCP-порт 443 по имени сервера:

  • SINHRON_TURN_HOSTNAME → Caddy снимает TLS и передаёт трафик TURN в coturn. Так звонки проходят даже в сетях, где открыт только HTTPS.
  • Всё остальное → HTTP-часть Caddy, которая видит реальный IP клиента:
    • SINHRON_PUBLIC_HOSTNAME → API сервера (/v1/*) и проверки /_healthz, /_readyz; остальное — 404;
    • SINHRON_LIVEKIT_HOSTNAME → сигналинг LiveKit по wss://.

Чтобы получать письма о проблемах с сертификатами, добавьте свою почту в глобальный блок Caddyfile: email you@example.com.

Звонки: LiveKit и coturn

Звонкам нужны два сервиса, оба уже описаны в docker-compose.yml:

  • LiveKit — медиасервер (SFU), который пересылает зашифрованные кадры между участниками. Сигналинг идёт через Caddy, медиа — через 7882/udp и запасной 7881/tcp.
  • coturn — TURN/STUN-сервер, который помогает устройствам за NAT найти друг друга. Работает в сети хоста, relay-порты — 49152–49999/udp.

Сервер Sinhron выдаёт пропуск в комнату звонка (JWT для LiveKit) только участникам чата, а временные данные для TURN — со сроком жизни до суток. Без переменных LIVEKIT_KEYS, TURN_SHARED_SECRET и TURN_URLS эндпоинты звонков отвечают 503.

Приёмка перед «продакшеном»

Обязательно сделайте реальный звонок между двумя физическими устройствами в разных сетях: телефон на мобильном интернете ↔ устройство на Wi-Fi. Затем повторите, когда одно из них в сети, где закрыто всё, кроме порта 443.

Apple Developer Account для самих звонков не нужен. Он нужен только для того, чтобы входящий звонок приходил при закрытом приложении; без него звонки работают, пока приложение открыто.

Проверка работы

Логи смотрите так:

Полезные строки в логах сервера: ws session authenticated — клиент подключился, message persisted — сообщение сохранено, rate-limited registration — кто-то слишком часто регистрируется (если такое повторяется, стоит разобраться).

Чек-лист безопасности

  • Вход по SSH только по ключу, пароли отключены, включён fail2ban.
  • ufw включён, открыты только нужные порты.
  • Порты 5432 (Postgres) и 8080 (сервер) наружу не открыты — только через Caddy.
  • Пароль Postgres длинный и случайный, .env с правами 600 и не попадает в git.
  • Обновления ОС ставятся автоматически (unattended-upgrades).
  • Настроен мониторинг доступности и есть запасной SSH-ключ администратора.
  • Docker compose запускается не от root.

Резервные копии

Сервер хранит только шифротекст, но без резервной копии пользователи потеряют недоставленные сообщения, зашифрованные копии состояния групп и файлы. Бэкап состоит из трёх частей: база Postgres, том с файлами sinhron_media и файл .env.

Откройте crontab -e и добавьте две строки: ежедневный дамп Postgres и архив тома с файлами (это шифротекст) — в тот же день, что и дамп:

В репозитории есть и готовый скрипт server/scripts/backup.sh: он делает все три части за раз — дамп Postgres, архив файлов и копию .env, зашифрованную GPG (пароль берётся из файла, указанного в SINHRON_BACKUP_PASSFILE), и хранит копии за последние 14 дней.

Если делаете вручную, файл .env сохраняйте только в зашифрованном виде:

Храните копии вне этой машины: на другом сервере или зашифрованном носителе. Дамп и файлы нужны вместе — записи в базе ссылаются на файлы в томе.

Восстановление на новой машине:

Не попадают в бэкап активные подключения (клиенты просто переподключатся) и недоставленные приглашения в группы — их отправят заново.

Обновление

Миграции базы применяются автоматически при старте сервера. Postgres и Caddy при этом не перезапускаются, а клиенты сами переподключатся через несколько секунд.

Пригласите людей

Сервер готов — осталось позвать собеседников:

  1. Расскажите им, где взять приложение (см. Начало работы).
  2. Дайте адрес сервера, например sinhron.example.com. Его нужно ввести при первом запуске на экране «Выберите сервер».
  3. Попросите надёжно записать 24 слова — без них аккаунт не восстановить даже вам как владельцу сервера.
  4. Новый чат начинается по QR-коду или по ключу собеседника — строке из 64 символов. При первой встрече сверьте код безопасности.
Регистрация пока открыта

В приложении есть поле для кода приглашения, но сервер коды пока не проверяет: зарегистрироваться может любой, кто знает адрес. Регистрации ограничены только лимитом частоты. Учитывайте это, если не хотите посторонних на своём сервере.

Спецификация рассчитана на сервер до 10 000 активных пользователей, но для семьи или небольшой команды хватит и минимальной конфигурации. Если пользователей становится больше сотни одновременно, увеличьте машину до 8 vCPU и 16 ГБ RAM.
