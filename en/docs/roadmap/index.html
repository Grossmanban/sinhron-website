Project

Roadmap

What’s done, what’s in progress and what’s next.

This page shows where Sinhron stands today and what comes next. It reflects the project's internal status tracking. We do not give dates: things ship when they are ready and tested.

Where we are

Sinhron is in early beta. The core is in place: end-to-end encrypted chats and groups, a working server, encrypted storage and backup, calls, several devices per account, sealed sender, and a polished messaging experience. The project's technical plan is divided into ten phases, from the first scaffolding to a security audit and store distribution. About eight of them are covered in code. Much of it still needs testing on real phones.

What is still missing before a public release is mostly about trust and reach: testing on real devices, an independent security audit, signed builds and distribution.

Done

Encryption and accounts

  • End-to-end encrypted one-on-one and group chats using MLS (RFC 9420).
  • Accounts without email, phone number or password, based on a 24-word BIP-39 key.
  • Encrypted backup of your chat membership on the server, restorable with your 24 words.
  • Fully encrypted local database (SQLCipher).
  • Message padding to hide exact lengths, and push notification payloads without content.
  • Safety numbers (60 digits or QR code, scannable with the camera) with warnings when a contact's key changes, including for each member of a group.
  • Sealed sender: the server sees neither which chat a message belongs to nor which account sent it. An optional SOCKS5 / Tor proxy also hides your IP address.
  • Several devices per account: link a new device by scanning a QR code; each device has its own key, and removing a device locks it out. Your main identity key stays on your first device only.

Server

  • Rust server with WebSocket delivery, offline catch-up, rate limiting and automatic cleanup.
  • Docker Compose deployment with automatic TLS (Caddy and Let's Encrypt).
  • Encrypted attachment storage.
  • Old messages are removed a whole month at a time.
  • Automated tests for the server, the encryption core and the app run on every change (GitHub Actions).

Calls

  • One-on-one audio and video calls through LiveKit, end-to-end encrypted with SFrame (RFC 9605).
  • Group calls with per-participant keys and a video grid (built; device testing pending).
  • Calls through restrictive networks via TURN over TLS on port 443.

Messaging experience

  • Replies, reactions, editing and deleting for everyone (within 24 hours), pinned messages shared with the whole chat, forwarding and multi-select.
  • Display names and profile photos, shared by each person inside the encryption; @mentions in groups; a Chat info screen.
  • Text formatting, including spoilers; large emoji; link and phone number detection.
  • Delivery and read receipts and typing indicators (both can be turned off).
  • Folders, archive, pinned and muted chats (reordered by dragging), drafts and swipe actions.
  • Fast on-device full-text search that opens the chat at the found message.
  • Disappearing messages, from 5 minutes to 4 weeks.

Privacy and comfort

  • App lock with Face ID, Touch ID or passcode, and a cover in the app switcher.
  • A single, honest privacy screen.
  • Blocking that stays on your device, a switch to turn off incoming calls, and message requests for chats someone new starts.
  • Themes (System, Light, Dark, Black OLED), six accent colours and chat wallpapers.
  • English and Russian.
  • Accessibility work: VoiceOver labels, large text, WCAG AA contrast, Reduce Motion.
  • Sounds and haptics.

In progress

  • Photos, video, files and voice messages. Implemented and tested in code, including albums, a gallery, recording video with the camera, voice messages with hands-free recording, and optional link previews. Video gets a preview frame and is compressed before sending. Still to do: verification on real devices.
  • Calls across networks on a real server. The setup for getting calls through NAT and firewalls is in place, but a full acceptance test on a deployed server with devices on different networks is still pending.
  • Testing on two real phones. Several devices per account, group calls and blocking are built and tested in code, but haven't yet been tried on real iPhones.
  • Push notifications and incoming calls when the app is closed. The server side is ready. The app side needs an Apple developer certificate, which has not been set up yet.

Next

  • First releases on GitHub Releases.
  • Security audit preparation, followed by an independent audit.
  • Reproducible builds, so anyone can check that a published app matches the source code.
  • Code signing and distribution: App Store, Google Play, F-Droid and desktop packages.
  • Builds for more platforms. Development currently focuses on iPhone; the Flutter codebase targets Android, macOS, Windows and Linux too.

Not planned for 1.0

Some things are deliberately left out of the first version:

  • A web client. Browsers make secure key storage and supply-chain safety much harder. It remains an open question for later.
  • Federation. Each Sinhron server is its own island. Servers do not talk to each other, and there are no bridges to other networks.
  • Post-quantum encryption. Planned once the MLS library we use supports it, without breaking existing chats.
  • Encrypted backup of message history. Version 1.0 backs up your chat membership, not your messages.
  • Cloud AI features such as translation or summaries. They conflict with keeping your data private.
  • Call recording.
  • Server-side search. This will never be built: search always runs on your device.
